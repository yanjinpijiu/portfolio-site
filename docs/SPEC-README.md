**运行状态**：并发下载占用（`0/20`）· 埋点队列丢弃数 · 验证码是否可用（服务器缺字体时会降级放行，看板上直接标出来）

访客识别方式（写进正文，体现取舍）：匿名 cookie ID 只用于算 UV；IP 用**离线 IP 库**解析省市（自制索引 `4.85MB`、`2423` 个地名、`502834` 条网段，纯内存二分查找，查询不出网）；UA 自己解析，不引 ua-parser；埋点**异步写库**（单线程 + 有界队列，容量 `2000`，满则丢弃并计数，不阻塞请求）；同一访客对同一路径 `5 秒`内重复上报去重；登录过后台的浏览器会种标记 cookie，**自己的访问不计入访客统计**。

### 3.7 下载三道闸（参数照抄）

| 顺序 | 机制 | 参数 |
|---|---|---|
| 1 | 单 IP 限流 | 每秒 `2` 次，固定窗口 |
| 2 | 验证码 | 同一 IP 对同一份简历，`24` 小时内前 `3` 次免验证；第 4 次起返回业务码 `428`，前端弹框 |
| 3 | 全局并发 | 最多 `20` 个下载同时传输；拿不到许可等 `2 秒`后拒绝（`429`） |

关键细节（都写进正文，这是这个项目最有工程味的部分）：

- 免验证的判断**复用下载日志表**，不额外维护计数器
- **只有成功下载才写日志**：验证码输错、被限流拦下都不记账、不消耗免费额度
- 验证码用 **JDK 自带的 Graphics2D** 画算术题（零依赖、可离线），答案存服务端内存 + `3 分钟` TTL，**先删后验**保证一次性核销（并发提交同一个验证码只有一个线程能成功）
- 答错即作废，前端自动换一张新图
- 服务器缺字体时（Linux 上的 JDK 不含字体、靠 fontconfig 找）**自动降级放行并打 ERROR 日志**；启动时渲染一张图数暗色像素做自检
- 简历的**存储路径不下发前端**：`/api/resumes` 只返回 id、标题、方向、文件名、大小、时间

### 3.8 静态 / 动态内容模式

| | 动态（默认） | 静态 |
|---|---|---|
| 内容来源 | 每次访问调 `/api/site` 实时查库 | 站点目录下预生成的 `snapshot.json` |
| 首屏 | 多一次查库往返 | 少这一个往返（`snapshot.json` 约 29KB） |

### 3.13 五条设计取舍（每条 2-4 句，讲「为什么」）

1. **鉴权边界只在服务端**：后台接口全挂 `/api/admin/**`，一个拦截器统一校验令牌（只放行登录接口），前端路由守卫只是体验优化。令牌随机 32 字节、存服务端内存并设过期时间，重启即失效（单实例够用）。
2. **只认 `X-Real-IP`，不认 `X-Forwarded-For`**：XFF 客户端能随意伪造，nginx 默认只追加不丢弃，拿它做限流等于没限——换个伪造值就得到一份新额度。`X-Real-IP` 是 nginx 用 `$remote_addr` 覆盖写的，后端又只监听回环地址，这个头可信。
3. **时间维度入库时算好**：`visit_date` / `visit_hour` / `visit_weekday` 是写入时就填好的冗余列，查询只做 `GROUP BY`。H2 的 MySQL 兼容模式函数不全，在 SQL 里调 `DATE_FORMAT` / `DATE()` 最容易翻车。
4. **后端要知道自己被反代了**：线上是「浏览器 https → nginx → 本机 http」，不开 `forward-headers-strategy: framework` 就会拿 https 的 Origin 跟自己的 http 比、判定跨域，把所有 POST 按 CORS 白名单拒掉。症状有迷惑性：GET 全正常、POST 全挂，而后台登录、埋点上报、简历上传恰好都在 POST 里。
5. **统计不引第三方**：访客数据既是个人信息、也是这个站最有价值的数据。自己实现（离线 IP 库 + 匿名 ID + 异步写库）少一个外部依赖，也不用把它交给别人（不需要 GA / 百度统计）。

### 3.14 已知边界（至少 4 条，照这个方向写）

- 令牌只在后端内存里，重启服务需要重新登录；多实例部署要换成 Redis 或数据库存令牌
- 统计数据会一直涨，现在靠索引扛（日均几十 PV 没压力），量大了可以加「清理一年前明细」的可选任务
- 登录接口在 nginx 上有 `20 次/分钟` 的限流；以后前面挂 CDN 的话 `$binary_remote_addr` 会变成 CDN 节点 IP，限流失效，需要配 `set_real_ip_from` + `real_ip_header X-Forwarded-For`
- 手机号会随页面公开；不想被爬就把后台「个人资料」里的电话清空，前台那一项会自动隐藏
- 后台界面与 ECharts 都是路由级懒加载，公开页面的包里不含它们

### 3.15 可选小节：上线后修掉的问题（3 条以内，每条 1-2 句）

1. IP 处理在「不带端口的 IPv4」上会崩：`127.0.0.1` 没有冒号，`indexOf(':')` 和 `lastIndexOf(':')` 都是 `-1` 却相等，于是走进「去掉端口」分支做了 `substring(0, -1)`。而 nginx 传来的 `X-Real-IP` 正好是这种写法——埋点一上线就会全量 500。
2. 线上所有 POST 一直返回 `403 Invalid CORS request`（就是 3.13 第 4 条那个问题），GET 却全部正常，是排查时最花时间的一处。
3. 公开的 `/api/resumes` 早期直接返回实体，把存储路径一起给了出去；简历和图片在同一个存储目录下、而 `/files/` 是公开发图的，拿到 key 就能绕过下载三道闸把文件拖走。现在对外只返回展示需要的字段。
